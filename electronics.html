Electronics

The fish is driven from a phone. Each button press becomes a single letter that travels by Bluetooth and then by radio to the Arduino inside the fish.

From button to fin

  1. PhoneDabble app in gamepad mode, paired with "RoboticFish" over Bluetooth.
  2. ESP32Reads the buttons every 20 ms and sends a letter only when a button changes.
  3. HC-12 radio433 MHz serial link at 9600 baud, ESP32 pins 16 and 17.
  4. Arduino UNOInside the fish. Receives on pins 8 and 9 and acts on each letter.
  5. Motor and servosRelay on pin 4 for the tail motor. Servos on pin 3 (rudder), 5 and 6 (fins).

Failsafe

Every letter the UNO receives, including the heartbeat, restarts a 1.5 second timer. If the timer runs out because the radio link has dropped, the UNO switches the motor off and puts all three servos back to centre. When letters start arriving again, it carries on.

// uno_fish_code.ino
if (!failsafeTriggered && (millis() - lastSignalTime > FAILSAFE_TIMEOUT)) {
  centerAllAndStop();          // relay off, servos to 1500 us
  failsafeTriggered = true;
}

Two things to test in water. Radio at 433 MHz only travels a short way through water, so the fish may need to stay near the surface with its antenna clear. And because the ESP32 sends each letter once, a lost S would leave the motor running while heartbeats keep the failsafe happy. Sending the current state with every heartbeat would close that gap.

Libraries

  • ESP32: DabbleESP32 for the phone gamepad, and the built-in Serial2 for the HC-12.
  • UNO: AltSoftSerial for the HC-12 and ServoTimer2Plus for the servos. AltSoftSerial uses Timer1, so the servos run on Timer2 to avoid a clash with the standard Servo library.

Code

esp_fish_code.ino runs on the ESP32 transmitter. uno_fish_code.ino runs on the Arduino UNO inside the fish.
